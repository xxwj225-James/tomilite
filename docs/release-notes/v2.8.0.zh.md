# TomiLite v2.8.0

**自 v2.7.0 起** —— 知识地图现在可以由你自己的活儿来填，而它下面那块任务计数已经删掉了。一个完成的任务、一个月的报告、一场会议的决定，都可以各自整理成一篇你自己的笔记，然后像你写的任何东西一样进入树、拥有链接、被搜索和语义近邻找得到。没有任何东西在后台生成：第一段免费点清来源，第二段产出候选笔记，你看过之前不会写入一个字。

## ✨ 新功能

- **把已完成的任务、报告月份、会议整理成知识。** 知识地图卡上按一个按钮就打开这个弹窗，它会列出有什么可整理的。每个来源出**一篇笔记**：任务整理出它是什么、怎么解决的；一个月的报告合并出当月的决定与结论；会议整理出它的决定和理由。三者都以普通笔记的形式落进笔记面板 —— 可编辑、可搜索、可链接，在知识地图里就是和你其他笔记一样的叶子。
- **一个月是一篇，不是三十篇。** 弹窗里 `任务` / `报告` / `会议` 三个来源各一个勾选框，外加时间范围（30 天、90 天、一年、全部），所以第一次面对几年的历史时可以从小的开始。当月从它第一份报告起就算候选；月中再按一次是就地合并进同一篇，不会另开一篇。
- **先看到数量，再看到账单。** 打开弹窗、或改动范围时，调用的是服务端那个**免费**的列表接口，它报告有多少来源够格，以及 —— 这才是关键 —— 其余的为什么不够格：*38 个没有内容可整理*、*22 个已经整理过*、*5 个还没完成*。这五种状态在屏幕上长得一模一样，需要你做的却是完全相反的事，所以每一种都点名说出来，而不是收成一句「没有结果」。
- **每一篇候选笔记在写入前都可以改。** 标题和整篇正文都是你的。关于一个月工作的初稿就是初稿，没有这个编辑框，你唯一能做的判断只剩「整篇不要」。
- **没看过的内容不会被写进去。** 你确认过的文本就是被存下来的文本 —— 写入时不会再问一次模型。如果这篇笔记在你审阅之后又被改过（被你，或被 Agent），那次写入会被拒绝并说明原因，而不是把改动盖掉。

## 🔧 变更

- **知识地图上的「项目脉搏」删掉了。** 待办 / 进行中 / 完成三个计数，加上最近任务与最近报告两个列表，整块移除。它描述的是一个项目，里面没有任何知识 —— 恰恰是一张笔记地图的反面。任务计数仍在任务面板自己的页签徽标上，那才是它该在的地方；`issue.taskCounts` 没有动，现在它是唯一的调用方。
- **知识地图的空态现在给出整理入口。** 那块条删掉之后，一本空笔记库会只剩下一张写着「没有笔记」的卡片和一个做不了任何事的按钮。而这一屏正是新用户会落到的地方，所以它现在会说明笔记从哪来，并带上那个能产出笔记的按钮。
- **「已导入」不再盖在本机写出的笔记上。** 这个徽标之前对任何带 source 的笔记都会出现，对会话纪要早就错了，再加上沉淀出来的笔记会更错 —— 那是你自己做完的活，却被标成从别处搬来的。现在只有真正的导入（`import:*`）才有它。
- **分类标签收口到一处。** 笔记列表以前对任何它不认识的分类直接印原始值，于是沉淀出来的笔记会在列表里显示 `task`、在地图里显示「来自任务」。两个界面现在调用同一张表（`apps/web/src/lib/noteCategory.ts`），它同时也给出了三个新分类的名字。
- **导入笔记现在只有一个按钮。** 导入弹窗以前按文件格式分成四块 —— 每块各一个隐藏输入框、一个按钮，还把同样的四件事各解释了一遍。现在只有一个：一次选择里挑任何支持的文件，由文件自己的扩展名决定交给哪个解析器。Markdown（`.md` / `.markdown`）、纯文本（`.txt`）、保存的网页（`.html` / `.htm`）、单页网页存档（`.mht` / `.mhtml`）可以在同一次选择里混着来，跑完只报一次 —— 一条进度条、一份汇总。格式按扩展名列出，不再按写出它的应用命名，这也正是四块能收成一块的原因。文件对话框一关不再立刻开跑：选中的文件会先列出来，每个名字后面写明它将被交给谁读，按下列表下方的按钮才开始导入 —— 于是选错是在列表上看出来的，而不是事后从汇总里读出来的。
- **这样导入的保存网页不带图片。** `.html` 导出的图片放在它旁边的 `<名字>_files` 文件夹里，而「选择文件」看不到文件夹 —— 于是每张图都变成一行占位，汇总里计数、明细里点名。弹窗在你开始之前就写明这一点，而不是让汇总来当那个意外。`.mht` 不受影响：它的图片在同一个文件里，所以在图片重要的场合，它是更该用的格式。
- **`.enex` 导入删掉了。** 选择器不再提供这个扩展名，也没有东西能读它。弹窗里也不再按应用名字列出格式 —— 那正是让某一个应用的导出菜单看起来像本应用功能的原因。

## ⚠️ 说明

- **整理是有单次上限的。** 每次 12 个来源，每个来源一次模型调用。两个上限都会如实报出来：弹窗会说有多少个超出本次上限、下次会从那里接着来；来源太长读不完时，它自己那篇笔记上会写明。12 次调用是你看得见、批得下的花销，300 次不是 —— 所以一整套积压需要按几次，而不是一次按完。
- **这个弹窗与聊天蒸馏共用同一把消费刹车。** 配额用尽时，整理会停下并告诉你是几点恢复 —— 后台的会话纪要也同样停。刹车是账号层面的事实，不是某个功能的事实；再开一把会让一个界面说「消费已暂停」而另一个照样继续试。
- **不让模型写 `[[链接]]`。** 它无从知道你库里有哪些标题，写出来的链接只会解析到空 —— 或者解析到两篇同名笔记里错的那一篇。整理完之后用笔记面板里的**补链接**；那条路知道库里有什么，并且会把候选给你看。
- **同一个来源整理两次是合并，不是多出一篇。** 该来源已有笔记时弹窗会写「并入……」，旧笔记会作为材料喂回去，里面已有的 `[[链接]]` 会保留。除非你勾上**重新整理全部**，否则它不会再问一次。
- **以前用 `.enex` 导入的笔记不受本次影响。** 删掉的是解析器，不是笔记：它们照常打开、搜索、编辑，来源也照旧显示「已导入」。变的是没**法再导更多**。另外有一处变安静了：加密段落（`<en-crypt>`）当年是那个解析器逐篇识别并计数的，所以汇总里不再会告诉你「跳过了几段加密内容」—— 其余格式里出现的加密内容会当成普通正文导入，也不会被单独计数。
