# TomiLite v2.3.0

**Since v2.2.0** — A look-and-feel release. Dark mode arrives, and the rest is subtraction: four entries off the bottom bar instead of ten, the agent's own bookkeeping out of your chat, five empty screens down to one, the theme picker off the toolbar and into Settings. No new agent capabilities.

## ✨ Features

- **🌙 Dark mode.** Light/dark is a new axis, independent of the four themes — every theme has both. It is a `data-mode` attribute written before React renders, so there is no white flash on start-up, and `color-scheme` is set so the native widgets follow: date and time pickers, checkboxes, select menus and scrollbars are no longer black-on-black.
  - **Turning it on meant fixing the token layer first.** The brand tints were hardcoded indigo — the button shadows, the update bar, blockquotes — so three of the four themes were already drawing indigo shadows under a blue or green brand _in light mode_. They now derive from the live brand colour. `color: #fff` on a brand fill goes through a token, and one heading was setting its text colour with `--surface`.
  - **Three light-mode colours were below WCAG AA** and moved: pipeline's muted text (3.00:1), hub's brand as a fill (4.23:1) and canvas's brand (4.51:1, passing with no margin).
  - **Your existing notes are safe.** The rich-text highlight and text colours are stored _inside the document_, picked for a white background. Under dark mode they would have rendered as light pink behind light text — unreadable, and in notes you had already saved. They are now resolved through the theme, so old notes re-colour themselves.
- **The bottom bar is four destinations plus "More".** It held ten, and ten was never going to fit: ten items at `min-width: 56px` plus the popup's own padding want 592px, while the chat column is only guaranteed 360px. So the row scrolled sideways precisely when a panel was open — that is, during actual work. Four items and the trigger need 280px, and the overflow is gone.
  - The fifth entry used to be **Chat**, and it was removed rather than moved into "More". The chat column is a _sibling_ of the panel, never covered by it, so "go to chat" revealed nothing that was not already on screen — a close button labelled as a destination. Each panel's own ✕ already does that job.
  - **"More" carries a plain red dot, not a number.** It briefly showed the sum of unread email and pending MCP approvals, which are two unrelated queues — the "3" it produced answered no question anyone has. The entries inside the list still show their real counts.
  - **The popup is anchored to the button that opened it**, and its **left** edge lines up with the trigger's. Matching right edges instead hangs a 172px list entirely to the left of a 56px button: measured at 319–491 with the trigger at 435–491, i.e. squarely over Tasks and Meetings while the button it belonged to sat just off its edge.
- **The session list is grouped by day** — Today / Yesterday / Earlier — because recency is the only thing telling one "Chat 26" from the next once the titles stopped being generated (see below).
  - **"Earlier" is folded by default**, and it is the only group that is: it has no upper bound, while Today and Yesterday are what you actually come back to. The header carries the count of what is behind it, and unfolds itself when the conversation you are in lives down there — a folded group would otherwise leave the sidebar with no active row. It does not re-open over a manual fold.
- **Settings → Appearance.** The toolbar used to carry five theme dots and a sun/moon button. Those are gone from the chat header entirely; theme and light/dark now live on a real settings page, and a small store is the single source they both read from.
- **Five panels now share one empty screen.** Notes, tasks, reports, meetings and email each had their own — two of them literally a bare `—`, one showing "no notes yet" even when the list was merely filtered to nothing. They are one component now, with an icon, a sentence and a button that leads somewhere real.
  - **A search that finds nothing is a different screen from a panel that is empty**, and they are drawn differently: an empty panel explains itself and offers an action, a search with no hits is one line.
  - **No empty state ever offers a creation flow that does not exist.** Notes, tasks and reports are all created on save, so their button clears the editor — the same reset their toolbars already did. The meeting button starts a recording through the ordinary consent dialog rather than around it.

## 🐛 Fixes

- **The agent's own operation log is out of your chat.** Every time a panel opened or closed, a `🔔 You opened X panel` bubble was appended — six zero-information bubbles filling half the screen in a single session. They are still produced and still reach the model, which is what they were for; a flag on the message now keeps them out of the renderer only. Nothing was dropped from what the agent sees, and the token meter still counts them.
- **Session titles are generated again.** The auto-title code was written, wired to every send, and permanently dead — its guard accepted only a title _exactly_ equal to `Chat`, while sessions are created as `Chat 26`. Repairing the guard alone would have changed nothing: it wrote to a different store than the one the sidebar reads. It now writes beside the list it edits, and to the database, so the title survives a restart.
- **Timestamps are read as the UTC they are.** `updatedAt` is written in UTC but was parsed as local time, so at UTC+8 anything done before 08:00 was stamped to the previous day and filed under "Yesterday".
- **Two colours in the `quantum` theme were the same colour.** `--brand` and `--green` were both `#76b900`, so "new chat", the active nav item and every completed state were indistinguishable — this was one theme's tokens colliding, not a surplus of green. The success green is now `#0d904f`. A side effect: the "low" and "medium" bars of the session token meter were also the same colour there, and are not any more.
- **The chat column's type scale is a scale.** It was using 9, 10, 11, 12 and 13px, and 51 of those 78 uses had no token behind them — the ladder is 11/12/14/16/20/24. Merged into the two that exist (9/10/11 → `--text-xs`, 12/13 → `--text-sm`, 81 places). The differences were not reading as hierarchy anyway: a card's field label was 9px while its own value was 10px, and a tool card's name was 10px while the body underneath it was 12px — the hierarchy was inverted. Weight and colour were already carrying it.
- **The meeting panel has room to breathe.** Widened to `clamp(420px, 46%, 680px)`, which surfaced a defect in the old rule: the panel basis could exceed what the row had left, pushing the whole app into a horizontal scrollbar — at the 900px minimum window, already. Both rules now carry a fit cap.
- **The feedback submit button said nothing while it worked.** Its "submitting" state and its disabled state were unreachable — one call was never made, so the button stayed live and silent through the whole request.
- **The email category chips were unreadable in dark mode.** Their colours were light-mode tints, near-white on a near-white background.
- **The morning and evening icons were the last hardcoded gradients** in the app, and were the only two saturated colours that did not follow the theme.
- **`0 action items` is not shown when there are none.**
- **Removed a dead update dialog.** It exported a check hook and a dialog that nothing imported — no import, no dynamic import, no string reference anywhere. The live update flow is a different component that registers its own listeners, so this one's listeners had never run.

## ⚠️ Notes

- **No schema change.** This release does not migrate your database.
- **The theme applies instantly and is remembered**, but on a cold start the window is still painted light by the main process before the renderer loads, so dark-mode users may see one light frame. The setting lives in the renderer where the main process cannot read it; fixing it properly means moving the preference to a file on disk.
- **The "More" popup uses CSS anchor positioning**, which is a Chromium feature. That is the only engine TomiLite ships on, so it is not a compatibility gap — but the two inset declarations before it are kept as a fallback, and in a renderer without support the popup falls back to the bar's own left edge.
- **Known and not fixed, recorded so they are not mistaken for oversights:**
  - **The success green fails AA on light backgrounds in all four themes** (pipeline 2.18:1, hub 3.19:1, canvas and quantum 3.93:1). The cause is that `--green`, `--amber`, `--purple` and `--blue` have no light/dark overrides in any theme — only `--brand` does. Giving all four a value per mode is a separate piece of work across 4 themes × 4 tokens × 2 modes, and is not in this release.
  - **The app has three parallel i18n systems** (`@/lib/i18n`, `@/i18n/translations`, and per-component three-way ternaries). Merging them is a mechanical change across the whole repo and unrelated to this one.
  - **`ChatSession.updatedAt` carries two clocks in one column** — `createSession` takes the database default `localtime` while `addMessage` and `renameSession` write UTC. A newly created empty session therefore sorts ahead of real ones. Fixing it touches the schema, a migration, and the distillation job that depends on the UTC stamp.
  - **The document language is always reported as English** regardless of the interface language. It affects screen readers and hyphenation, not anything visual.
