# TomiLite v2.6.0

**自 v2.5.0 起** —— TomiLite 现在真正会说 MCP 了。「把你的任务暴露给 Claude Code」这句话，就*工具*而言早就是真的，就*协议*而言从来不是：唯一的入口是一个长得像 MCP 却并不是的 HTTP 端点，任何现成客户端都连不上。现在有了两条真正的传输，两代协议都支持，设置页给出的配置也真的能用。顺带：三份互相矛盾的目录合并成一份，修掉四个缺陷，其中两个你今天就可能踩到。

## ✨ 新功能

- **TomiLite 现在是一个标准 MCP 服务端。** 设置 → API 密钥会给出两种传输各自可直接粘贴的配置，并把本机安装的真实路径填进去 —— 安装程序允许用户自选目录，所以这些路径没法预先写死。

  - **stdio。** 配置里启动的「服务端」就是 `TomiLite.exe` 自己。安装包不带 `node.exe`，也不带 `tsx`，所以应用是以 `ELECTRON_RUN_AS_NODE=1` 跑自己那份脚本 —— 这个模式下 Electron 根本不加载主脚本：不开窗口、不碰单实例锁，进程就是 MCP 客户端的一个普通 Node 子进程。
  - **StreamableHTTP。** `POST http://127.0.0.1:<端口>/api/mcp`，密钥放在 `X-Api-Key` 头里，给那些用 HTTP 而不是 stdio 的客户端。只接受本机来源；`GET` 与 `DELETE` 返回 `405` —— 没有 SSE 流，也没有会话可供枚举。
- **两代协议都支持，而且按每个请求分别判定。** 最新修订版（2026-07-28）整个移除了 `initialize` 握手 —— 每个请求自带 `_meta` 信封，服务端无状态 —— 而现实中所有客户端仍然以 `initialize` 开头。谁问什么就答什么，判据只有一个（这个请求带不带信封），这也是 HTTP 端点不需要会话 id、也没有服务端状态可丢的原因。探测新版协议的客户端会拿到真实答复和版本列表，不探测的照旧走老握手。
- **等待审批不再表现为超时。** 以前审批发生在一次五分钟的 HTTP 长轮询里，而 MCP 客户端普遍在一分钟左右就掐断工具调用 —— 于是模型拿到一条它无法解释的传输错误。现在的等待是刻意做短的；等不及的那次调用会明确回来说**尚未执行任何操作**，动作正在 MCP 面板里等批准，请用完全相同的参数再调一次，或用新增的 `get_task_result` 工具取结果。
- **批准来晚了也不白批。** 面板上那个「批准」按钮自己会执行工具、把结果留在任务上，所以客户端已经放弃之后才点批准，动作照样完成 —— 而且 `get_task_result` 照样取得回来。
- **读操作不问审批，也不需要问。** 只读调用直接执行，不再被登记成审批任务，所以同一个读操作调两次就有两次数据。
- **新增 `get_board_status`** —— 你的看板，逐列给出 WIP 上限与卡片数；同时移除了一个只宣传、从未实现的工具（`update_settings`，语义不清，等于开一个任意改配置的口子）。凡是宣传的工具都调得通，而这一条现在有端到端检查兜着，不靠人看。
- **API 密钥的 scopes 真的生效了。** 不带 `write` 的密钥无法调用任何会改东西的工具。本版之前签发的密钥都已经是 `read,write`，对它们毫无影响 —— 这条恰好在本版让第三方客户端持钥成为可能的时候开始有意义。
- **选中的笔记可以一次性删掉。** 笔记一览一直支持多选，但多选只有一个去处 —— 导出，于是想清掉三十篇，就得在一张已经勾好了的列表里来回三十趟编辑器。现在只要有选中，工具栏就会多出一个删除按钮；表头勾选框会选中当前筛选结果的**全部**（跨分页）；确认弹窗会边删边报进度 —— 删除是每篇一次往返，选得多了否则就像卡死了。某次删除里有失败时会如实说，而且数的是**真正删掉的**篇数（「N 篇删除失败，其余已删除。」），不是尝试过的篇数。**顺带修掉一个此前看不见的 bug**：「全选」是按笔记**正文**过滤的，而列表早就因为投影收窄不再加载正文了 —— 于是一个只命中**分类**的搜索词会把这篇文章显示出来，却在选中时悄悄把它漏掉。现在两者问的是同一个问题。

## 🔧 变更

- **导入从设置里搬到了产出结果的那个面板。** 笔记导入的那一半产出的是笔记库，Redmine 连接的那一半产出的是任务板 —— 两个都不是「设置」。它们现在是各自面板工具栏上的弹窗，空库时还会出现在空态里 —— 而那正是「我的笔记 / 工单在别处」这件事最成立的时刻。**导入完会直接刷新它写入的那个列表**：以前靠「切回面板时会重新拉取」，而功能一旦搬进面板内部，这个前提就不成立了。
- **Markdown 导入改成选文件，不再选文件夹。** 原先的文件夹选择器去掉了，弹窗现在可以一次选中任意多个 `.md` / `.markdown` / `.txt` —— 从别处导出之后，手里本来就是这样一堆文件。两个后果都处理了，而不是留给你去发现：文件选择不带目录信息，所以「笔记本」原本来自子文件夹名，现在改成弹窗里的可选**分类**字段（留空则归入 `imported`）；文件只能靠文件名识别，所以一次选中两个同名文件时，汇总里会明确写出「同名被略过」，而不是让其中一个悄悄顶掉另一个。如果你之前是选*文件夹*来让子文件夹变成分类：现在请改为选中文件、再手填分类名 —— 分组从一个目录变成了一个字段。

## 🐛 修复

- **批准后重试，拿回了状态却没拿回答案。** 幂等重放分支把任务的状态原样回显，却漏了它的结果，于是一个已批准并执行完的写操作返回 `approved` 和别的什么都没有 —— 且是永久性的，因为重试命中的还是同一条重放。同一个疏漏还让只读调用（它*确实*被登记成了任务）在你第二次调用时完全拿不到数据。两者是同一行代码。
- **`get_report` 可能返回 500 而不是一条错误。** 它的 schema 声明 `id` 必填，运行时校验器却没有，于是不带 `id` 的调用会走到一个以 `undefined` 为键的数据库查询。必填字段曾经有两份列表，现在只有一份、从 schema 推导 —— 于是这种不一致在结构上不可能发生，而不只是被修好了。
- **MCP 面板把成功的批准显示成失败。** 批准按钮判断的是一个后端从未返回过的字段，于是每一次成功的批准都渲染成出错。现在按它真正返回的状态判断。
- **工具表、风险表、以及实现，是三份已经漂移的列表** —— 一份公布 17 个名字，一份实现 15 个，一份带 14 份 schema。有两个名字可以被调用、可以排进审批队列、可以等人批准，然后回一句 `Unknown tool`。现在它们合成一份目录；调用一个不存在的工具会在**任何审批任务被创建之前**就作为协议错误拒绝掉。
- **浏览器里带 `X-Api-Key` 的 `POST` 过不了 CORS 预检**，于是从页面上根本发不出任何 MCP 调用。现在 `X-Api-Key` 与协议自己的那几个头都在允许列表里。
- **非本机的 MCP 客户端会被要求一个它根本拿不到的令牌。** 该端点对桌面令牌的豁免，判的是带点的前缀，而裸端点地址并不匹配。现在改为精确匹配。

## ⚠️ 说明

- **没有新增依赖。** MCP 协议是直接实现的，客户端和服务端两半本来就都是。安装包多了一个打包文件，没有多一棵依赖树。
- **需要重新安装才能拿到。** stdio 脚本是打包时生成的构建产物，所以只替换数据库 schema 的升级方式不够 —— 请用新的安装包。
- **待审批不跨重启保留。** 审批队列活在运行中进程的内存里。退出 TomiLite 会丢掉所有还在等待的项：退出前先批准，或者重新发起那次调用。要彻底修好需要给审计表加一列，本版有意不做。
- **API 密钥的过期时间只显示、不生效。** 过期的密钥仍然能通过认证。这一列从未对已有数据做过格式核查，而按错误假设写出的比较会一次性把所有密钥锁在门外，所以这件事需要先做一次存储层面的核查。在此之前，把那个日期当成给自己的备注，不再信任某把密钥时就**撤销**它。
- **密钥失效会告诉模型。** 无效或已撤销的密钥被报成*工具*失败而不是协议故障，于是助手能读到「这个密钥无效，请去 设置 → API 密钥 重新生成」并转告你，而不是由客户端弹一个看不懂的协议错误。
- **`POST /api/mcp.execute` 没有任何变化。** 已经对接老端点的调用方 —— 包括照着设置页旧说明做的那些 —— 行为完全不变。旧说明的问题在于它描述了一份任何 MCP 客户端都用不了的配置；端点本身没问题，而现在两条新传输调的都是它。
- **飞书、企业微信这类云平台不在本版范围。** 它们是云服务，需要一个公网可达的入口，那是另一件事 —— 是中继，不是传输层。本版加的 StreamableHTTP 端点正是那件事要复用的协议部分。
