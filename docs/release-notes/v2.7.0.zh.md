# TomiLite v2.7.0

**自 v2.6.0 起** —— 笔记导入终于又能读印象笔记了，因为印象笔记不再写 TomiLite 读得懂的那个文件。其 Windows 客户端已经不再提供 `.enex`，客服的说法是改用 `.notes`，导出菜单里给的是 `.notes`、`.html`、`.mht`。于是这条以该应用命名的导入通道，恰好成了它的用户导不出来的那一个。现在 `.html` 与 `.mht` 都支持，都在渲染层解析、不加任何依赖，而 `.enex` 保留给那些客户端仍然写它的用户。

## ✨ 新功能

- **导入印象笔记的网页导出（.html）。** 请选它导出的**整个文件夹**，不要选里面的文件：每个 `.html` / `.htm` 变成一篇笔记，图片从它旁边的 `_files` 文件夹里读 —— 所以只选文件是带不出图的。笔记归入导出文件夹的名字（会剥掉 `.notes` 中缀，所以 `Travel.notes.html` 归入 `Travel`）。
- **导入印象笔记的单篇导出（.mht）。** 一篇笔记的正文、图片、附件都在那一个文件里，所以一次多选本身就是完整的 —— 与 `.enex` 同形。图片的内嵌方式与 `.enex` 导入相同；字符编码、quoted-printable 与 RFC 2047 头都会解码，所以中文标题就是中文，而不是 `=?GB2312?B?…?=`。
- **同一次导出重导会跳过已有笔记**，两种新格式都与 Markdown、`.enex` 一致。在 TomiLite 里改标题**不会**多出一篇：网页导出的身份是它来自哪个文件，不是它的标题。

## 🔧 变更

- **`.enex` 那一格现在以写出该格式的应用命名**，并直接写明印象笔记 7.x 已不再产出它。「印象笔记导出文件（.enex）」是在给每一位印象笔记用户指一条他自己的客户端里不存在的路 —— 这比缺一个功能更糟，它是一条错误的指引。
- **导入弹窗里恢复了选文件夹 —— 只给网页导出这一格。** Markdown 在 v2.6.0 刻意去掉了选文件夹（文件夹会拖进几百个不是笔记的文件，换来的只是一个很大的「已忽略」计数）。网页导出恰好相反：那些文件**就是**载荷。Markdown 那一格没动。
- **一个 HTML 文件 = 一篇笔记，若不符合会如实告诉你。** 单个文件里若有多于一个笔记分隔标记，汇总会说有几个 —— 但不切分。切分需要一个能分辨「笔记边界」与「剪藏网页里满地都是的空锚点」的判据，而手上这份导出证明不了它。判据猜错**不是降级**，是把一个笔记本撕成碎片，每片还带上一套编出来的标题和 id。
- **两个新的体积上限。** 单个笔记文件 32 MB（一个 HTML 文件到这个尺寸，等于整个笔记本导成了一页，宁可拒收也不做成一篇 32 MB 的笔记），单个 `.mht` 100 MB —— 与 `.enex` 同一个数字，因为两者都是「一个文件装一篇笔记的全部资源」。
- **知识地图下方恢复了任务与报告。** 这块叫「项目脉搏」：任务待办 / 进行中 / 完成三个计数，加上最近完成的三个任务和最近的三份报告，点一下跳到对应的面板。地图本来只读笔记 —— 因为树上的叶子**就是**笔记 id，任务和报告没有 id，放进树里那一整块（打开笔记、`[[链接]]`、语义近邻）就都走不通了。但这一版地图替换掉的那张旧卡片，读的是**任务、笔记、报告**三个来源，只留笔记等于把项目说窄了。所以它们不进树，而是放在树旁边，用的是任务面板自己的状态词与同一套计数逻辑，不会出现首页和看板各说一个数的情况。
- **代理关掉之后，搜索恢复可用。** Windows 关闭代理时会把 `ProxyEnable` 清零，却把地址留在 `ProxyServer` 里，而 TomiLite 只读了地址、没读那个开关 —— 于是每次搜索都被投进一个没人监听的端口，返回一个空结果列表，读起来像「没有匹配」，而不是「网络不通」。现在系统代理按它本来的三个注册表值来读：开关、地址、绕过列表。绕过列表也生效了，所以一个**能用**的代理不再拦下你明确排除掉的内网地址；而一个连不上的代理会退回一次直连，不再把整个回合一起拖下水。

## ⚠️ 说明

- **没有新增任何依赖。** MIME 容器解析是本仓库里约 200 行代码，而且是**按字节**走而不是按字符串 —— WHATWG 编码标准把 `iso-8859-1` 别名成了 windows-1252，一个会把 `0x80`–`0x9F` 全部改掉的解码器，不是能拿来切分容器的解码器。
- **这两个解析器只对着一份真实导出验证过，而且那份只有一篇笔记。** 格式是从一份 3374 字节的 `.html` 和它 820 KB 的 `.mht` 孪生文件读出来的。样本**确实**确立的东西都写进了代码：没有 `<en-note>` 容器，笔记分隔标记是自闭合的 `<a name="…"/>`，每个文件的 `<title>` 都是格式自带的 `Evernote Export`（所以它被拒绝作为标题，而不是发给每一篇笔记），图片引用是纯相对路径外加一个 `?t=attachment` 查询串，全文没有任何逐篇日期 —— 所以导入的笔记取导入时间，而不是一个其实是「导出发生时刻」的时间戳。一份样本**无法**确立的是：单页导出是否真的一个文件对应一个笔记本，以及导出里到底有没有逐篇标题。两处都按保守而非聪明的做法处理，也都写在了下一个人能找到的地方。
- **不支持 `.notes`。** 加密私有格式，无公开规范、无任何第三方解析实现；社区对它采用的迁移路线是 `evernote-backup --backend china`，产出的正是 TomiLite 已经能读的 `.enex`。
- **导入不是备份。** 因为笔记按 `sourceId` 归并，一次导入可以覆盖你在 TomiLite 里改过的笔记（勾选**覆盖**即如此）；也意味着在 TomiLite 里**删掉**的笔记，会在下一次导入同一个文件时回来。导入是单向的，这是设计如此。
