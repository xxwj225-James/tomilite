# TomiLite v2.5.0

**Since v2.4.0** — your existing work can move in. Notes come from a Markdown folder or an Evernote export, and the tickets assigned to you on a company Redmine appear on the task board as read-only mirrors, so the health score, the morning brief and the agent finally see the workload that was never in here. Plus three latent defects found while designing it, two of which would have eaten data.

## ✨ Features

- **Import notes from a Markdown folder or an Evernote `.enex` export.** Settings → Import. Pick a folder and every `.md` / `.markdown` file under it (subfolders included) becomes a note; pick an `.enex` and every note in the notebook does. The notebook or top-level folder name becomes the note's **category**, so imported material stays grouped the way you filed it rather than landing in one pile.
  - **Re-importing skips what is already there.** Notes are matched on their origin (a file's path inside the folder; for `.enex`, the note's creation second plus its title), so running the same import twice reports "N skipped" and changes nothing. **Overwrite** is a separate choice, off by default — the second import of the same folder must not silently discard edits you made in between.
  - **Pictures are embedded, everything else is a placeholder.** Images become inline data so the note reads like it did in the original, under a size cap; other attachments leave a line naming the file. The cap is deliberate and small: the search index keeps its own copy of every note body, so an image-heavy note grows the database at roughly twice its size and stops matching meaningful searches.
  - **Encrypted Evernote notes say so.** A note whose body is `base64:aes` ciphertext, or that contains `<en-crypt>`, cannot be decrypted here — Evernote does not export the key — and it imports as a placeholder count rather than as a note that looks empty. The wording says why, so it does not read as a parser failure.
  - **The note editor's category menu now shows the value it actually has.** Its dropdown offered four fixed categories while the app had been writing a fifth (`chat`) for a while, and a `<select>` whose value matches no option renders **blank** — so those notes looked uncategorised, and picking anything from the menu to "fix" it moved the note out of its notebook for good. An unrecognised category is now its own entry in the list.
- **Import the Redmine tickets assigned to you.** Settings → Import → From Redmine: give the server address, an API key and a project, and TomiLite pulls the issues assigned to that key's user on a schedule (4 minutes after launch, then every 30 minutes), plus a **Sync now** button and a **preview** that shows what a sync would do without writing anything.
  - **One direction, and read-only here.** Nothing is ever sent back to Redmine, and a mirrored ticket cannot be edited, deleted or dragged on the board — the next sync would overwrite a local edit and re-create a local delete, so the controls are absent rather than silently futile. That single direction is what makes the copy safe to keep.
  - **The tickets count as your tasks, everywhere.** They appear in the board's counts, the Home totals, the health score, the morning brief's overdue list and the agent's view of your workload. This is on purpose: the sync asks Redmine for **issues assigned to you**, so what enters your statistics is your actual queue, not some project's throughput.
  - **Your tickets keep your task numbering, and theirs keep theirs.** A mirrored row shows Redmine's own `#1234` — the number your colleagues, commits and email threads use — while `TL-` numbers stay reserved for tasks this app creates. It also means a commit message mentioning `#1234` can no longer close a mirrored ticket from the Git panel; the link is still recorded.
  - **Nothing is trusted about a server's vocabulary.** Trackers, statuses and priorities are read from your server and cached, because they are per-install and usually in your own language. Whether a ticket is closed is decided by the status's own flag, never by its name, so renaming "Closed" to something else cannot corrupt the mapping.
  - **A ticket you don't want can be detached** from the task editor: it becomes an ordinary local task you own and can edit, and the sync stops maintaining it. Detaching tells you the ticket will come back as a new copy on the next sync, which is the honest consequence of clearing the link rather than a bug.
  - **Disconnecting offers three answers and requires one**: keep the mirrored tasks, detach them all into local tasks, or delete them. There is no default, because "keep" leaves rows that are read-only *and* no longer refreshable — a dead end you should choose, not fall into.
  - **Plain `http://` is allowed and warned about.** An intranet Redmine is the normal case, so TLS is not required; the settings screen says plainly that the key travels in the clear on that leg. The API key itself is encrypted at rest and never sent back to the interface.
- **The Import tab warns you before a large import.** It reads your current note count and says when a folder will push you past the size at which the knowledge map falls back to a category tree.

## 🐛 Fixes

- **The hourly cleanup was deleting finished tasks, not hiding them.** The sweep's own comment said "hide from UI, never delete" — true for commits and emails, which are flagged archived, and false for tasks, which it deleted outright along with their comments, changelog, git links and board cards, and which it left as parentless orphans if they had subtasks. Anything you completed and then left alone for 90 days was gone. **Mirrored tickets are now excluded from that sweep**, which was the urgent half: a closed Redmine ticket maps to a finished task, closed tickets are overwhelmingly older than 90 days, and the sync cursor has already moved past them — so importing 400 tickets would have become 87 within the hour, permanently and with no error. The sweep still deletes *your* old finished tasks, unchanged from before; that is now written down where it happens instead of being described as a hide.
- **The notes panel was loading every note's full body to show a list.** Opening Notes fetched the entire library — bodies, embeddings and all — into the window and kept it there, then paged through it 20 rows at a time. Every refresh paid it again. It is now a projection (title, category, dates) and a note's body is fetched when you open it, which is what the refresh path already did.
- **Your own tasks can no longer be pushed out of the task list by an import.** The board fetches at most 200 tasks, newest first, and counts its badges over all of them — so a few hundred freshly-synced tickets, all with recent timestamps, could fill those 200 slots and leave a tab showing nothing while its badge said 37. Your tasks now sort ahead of mirrored ones and take the slots first; the badges still count everything.
- **Tasks created while a sync is running can no longer share a number.** `issue.create` read the highest task number and then inserted, outside a transaction. A sync writing a few hundred rows in that gap would leave two tasks with the same number, and everything that identifies a task by its number — the editor, the agent, the MCP server — picks one arbitrarily. The number is now read and used inside the same transaction.
- **A note's embedding represents its text, not its screenshots.** Notes with embedded images handed the whole base64 payload to the local embedding model, which tokenises it and then truncates at 512 tokens — so for an image-heavy note, the vector described the image data rather than the writing, and that note was semantically unfindable. Data-URL images are stripped before embedding, for existing notes as well as new ones.

## ⚠️ Notes

- **This release adds two columns to `Issue`** (`source`, `sourceId`) at `SCHEMA_VERSION` 25 → 26, both plain additive `ALTER TABLE`s — no table is rebuilt, no row is touched. Every existing task has `NULL` in both, which is exactly the value meaning "written by this app", and every existing writer keeps writing it.
- **Importing is a copy, so a copy can age.** A mirrored ticket reflects the last sync, not the last five minutes; the sync interval is 30 minutes and **Sync now** is there when you want it sooner. Nothing about your Redmine changes, ever.
- **Imported notes carry their folder as a category**, which will not match the app's own four. That is intentional — the category records where the note came from — and the editor now displays it properly rather than showing a blank.
- **A `.enex` file larger than 100 MB is refused** with a message asking you to split the export. The whole file has to be read as text, and building a single document from one that size would take the app down; a per-notebook export is the workaround.
- **The `.enex` reader is new and has not been tried against a real export.** It is written from the format's specification, and the Markdown-folder import shares none of its code. If an Evernote import produces empty or oddly-formatted notes, that reader is the thing to look at, and a sample file is the thing that would settle it. Please open an issue with the file's shape (not the file) if you hit one.
- **Redmine's REST API can be switched off server-wide.** When it is, the server answers with an HTML error page rather than JSON, which TomiLite now reports as a readable failure instead of crashing. A rejected API key is reported separately, so you can tell "the API is disabled" from "this key is wrong".
- **If your Redmine is only reachable through a proxy, that proxy is used** — the same system proxy setting the AI features use. An intranet Redmine reached from outside the LAN needs it.
