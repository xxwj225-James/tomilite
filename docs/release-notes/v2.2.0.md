# TomiLite v2.2.0

**Since v2.1.3** — Two things the agent simply could not do before: open a link, and read your meetings. A pasted URL was unreadable, so "what does this page say" burned every turn on guesses; meeting data was invisible to every tool, so questions about decisions and action items had no answer. Both have tools now — and a turn that still runs out of turns says so instead of printing `(no response)`.

## ✨ Features

- **🔗 Tomi can open a link** — a new `fetch_url` tool. Before it, there was no path at all to a web page: `web_search` queries a search engine and returns titles and snippets but never fetches a result, `curl` and `wget` are blocked by the shell tool's allow-list, and no GitHub MCP server is configured by default. Ask about a pasted repository link and the agent would spend all ten of its turns on `ls` and `grep` variations that cannot work on Windows, then answer nothing.
  - **GitHub links are rewritten** to endpoints that actually return content. github.com renders repository, `blob` and `tree` pages client-side: fetched as-is, a repo page is about 15 KB of GitHub's own navigation with no README in it. A repo link now resolves to its README, a `blob` link to the raw file, a `tree` link to a readable directory listing. Relative links inside a fetched README are rewritten to absolute URLs, so the one link that answers the question can be followed on the next call instead of becoming `https://docs/meetings.md`.
  - **It is guarded.** http and https only, one URL per call, a single 15-second deadline covering the whole redirect chain, a cap on both how much is downloaded and how much is handed to the model, and a private/local address check on **every** hop rather than only the first. That last one matters here: this API exempts localhost from its token check, so a page that told the model to fetch `http://127.0.0.1:3192/api/...` would otherwise reach the app's own API.
  - **Fetched content is data, never instruction.** Nothing a page returns is auto-executed, and the tool description says so outright.
- **🗂 Tomi can read your meetings** — two read-only tools, `list_meetings` and `get_meeting`. Meetings live in the app database, which `shell_exec` and `search_local_data` cannot see, so "what did we decide about X" previously had no answer other than reading source files. `list_meetings` filters by status, title fragment and archived state; `get_meeting` returns the summary, decisions, action items and minutes for one meeting, and includes the transcript only when it is explicitly asked for — it is the expensive field, so it is opt-in.
- **The sandbox is now described, not discovered.** The system prompt spells out which commands `shell_exec` accepts, and two consequences the model previously had to learn by failing: `ls`, `cat`, `grep`, `find` and `type` are Unix commands and do not exist on Windows, and `curl`/`wget` are refused outright. It is also told to name a missing workspace root rather than spend turns on command variations.

## 🐛 Fixes

- **A turn that ran out of turns now says why.** When the agent hit its 10-iteration limit, the literal string `(no response)` was written into the chat — no explanation, and no way to tell it apart from a broken model or an empty reply. The API now reports a localized reason for both cases: the iteration limit was reached, or the model returned nothing.
  - The forced-summary call that ends a capped turn was itself offering the full tool list, so a model asked to "summarize what you found" could answer with one more tool call — which the caller discards, leaving the reply empty. That is what produced the blank turn in the first place. The summary call now offers no tools.
  - `finish_reason` and the token limit are logged, so a truncated answer can be told apart from a silent one.
- **Meeting audio retention is actually enforced.** `retentionDays` was stored, displayed in the UI, and never acted on — audio stayed on disk forever. An hourly sweep now deletes the audio of meetings past their retention window, and only the audio: the transcript, summary, minutes, decisions and action items stay. Anything still recording or transcribing is skipped, `retentionDays: 0` still means keep forever, and the deletion is stamped so it is not attempted twice.
- **New recordings honour the Settings defaults.** `meeting.create` passed its own hardcoded `lang: 'auto'` and its own retention default, so the language and retention you chose in Settings were ignored for every recording started from the UI. The server-side defaults now govern, and the entry point no longer overrides them.
- **Meeting duration is reported in seconds.** Duration was rounded to whole minutes, so every meeting shorter than 30 seconds read as `0` and looked like missing data. Both seconds and minutes (one decimal) are returned.
- **The meeting estimator's hosted-model flag was read from a field the API does not return**, so one branch of that check could never be true. The flag is now read from the field the API actually sends.

## ⚠️ Notes

- **No schema change.** This release does not migrate your database.
- **The installer is unchanged in size** — 185.8 MiB, about 6 KB larger than v2.1.3. No new native dependency.
- **`fetch_url` has one known gap.** A hostname that resolves to a private address through DNS is still fetched, because the HTTP client re-resolves the name after the check. Closing it requires pinning the resolved address, which is not done. Literal private addresses, `localhost` and internal names are refused, including on redirects.
- **`fetch_url` reaches the public internet.** It is the only tool that fetches a page you or the model names. It sends no credentials and cannot run anything it reads.
