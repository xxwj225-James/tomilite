# TomiLite v2.1.3

**Since v2.1.2** — Search that actually works in Chinese: the full-text index is rebuilt on a trigram tokenizer and semantic search now runs on a local model. Chats also distill themselves into notes, and meeting decisions become rows with a rationale, a follow-up draft and reminders.

## ✨ Features

- **🔍 Retrieval, rebuilt** — Chinese full-text search was silently returning nothing. The index was built with `tokenize='porter unicode61'`, which treats a whole run of Han/Kana as **one** token, so a CJK query only matched when it equalled an entire indexed string: `迁移` and `数据库` found zero rows while `迁移决定` found one.
  - The index had also been duplicating on **every boot** — 1,616 source rows had grown to 498,107 index rows, 1.43 GB, 95% of the whole database. Rebuilding on `trigram` fixes the search and reclaims that space: the index is now exactly one row per source item.
  - The rebuild is self-healing. It runs before the API starts listening, in one transaction, and any failed precondition means it simply retries on the next boot instead of being recorded as done. A drift guard compares the index against the source tables every startup, so the unconditional repopulate that caused the bloat cannot come back unnoticed.
  - Queries are quoted before they reach the index, so `id-1` and `a"b` are searched instead of raising a syntax error. The `type` column is no longer searchable text.
  - Reclaiming the freed space happens **two minutes after** the window opens, never during startup.
- **🧠 Semantic search, on your machine** — notes and reports can be matched by meaning, not just by keyword, using a local **multilingual-e5-small** model (q8, 384 dimensions) running in-process. Because it is multilingual, a Chinese question can find a note titled in English.
  - The model is **not** in the installer. It is downloaded on first use (~135 MB, checksum-pinned) and, until it arrives, search degrades to keywords — it never errors and never blocks a turn.
  - The previous remote embedding path is gone. It was dead for DeepSeek (the default), Anthropic and the hosted gateway, and actively harmful for OpenAI and Qwen, which stored a 1536- or 1024-dimension vector in the same column a 384-dimension query reads — a silent length mismatch that ranked those rows last forever.
  - Vectors now record the model that produced them, so a vector from another model is a miss that forces a recompute rather than a wrong-width array. Writes are centralised on a queue with triggers, so **every** note and report write path re-embeds — including paths added later — and an edit can never leave a stale vector behind.
  - The agent's `search_notes` is now a real hybrid: keyword (BM25) and semantic results fused with reciprocal rank fusion. Results carry the note id, so the agent can open what it just found.
- **📝 Chats that leave a note behind** — a long conversation used to die with its session. Now, once a session has been idle for 3 minutes with at least 6 new messages, the model folds that window into **one rolling note per session** in the Notes panel: decisions and their reasons, standing preferences, project facts, conventions, unresolved threads. Chit-chat, restatements and anything already in the note are dropped.
  - The note is rewritten, not appended, so a session's note stays a summary instead of becoming a log. It is indexed like any other note, so it is immediately searchable.
  - The watermark advances only after a successful write, so a crash or a bad response replays that window instead of losing it.
  - This runs on the LLM you configured, in the background — so it has brakes: a 30-minute backoff per session, a 6-hour pause if the gateway reports exhausted quota or a disabled account, and it can be switched off entirely with the `distill.enabled` setting. Tokens and cost are recorded per run and reported to telemetry as **aggregate counters only** — never note text or titles.
- **🗂 Meeting decisions as rows** — decisions were a JSON string rendered as a read-only list, so they could not carry a rationale, a date, or any per-item action. They are now rows, and existing meetings are migrated automatically.
  - A rationale is recorded only when the transcript actually states one — **never inferred**.
  - A follow-up draft is written from the summary, decisions and action items only, never from the transcript, so its cost does not grow with meeting length.
  - Two reminders go out through the normal Windows notifications: an action item due tomorrow, and a meeting that is N days old and still has open items. Both dedupe on the row, so a restart cannot notify you twice. Mail remains **draft-only** — nothing is ever sent automatically.

## 🔒 Privacy

TomiLite stays local-first — tasks, notes, emails, reports, chats, meeting recordings and transcripts, API keys, git data and **search indexes** live in your own SQLite database under `~/.tomilite/`.

Search embeddings are computed **on your device** by a model that runs in your app; note and report text is not sent anywhere to build the index. The only network calls retrieval makes are the one-time model download and the LLM calls you configured. Chat distillation is the one feature that sends conversation text to your LLM provider on its own — it is disclosed above, is metered like any other call, and can be turned off.

## ⚠️ Notes

- **The installer grows by about 29 MB** (157 MiB → 186 MiB). On-device embeddings need the ONNX runtime, which ships with the app. The model itself does not.
- **Two-character Chinese queries** still cannot be served by a trigram index — that is structural, not a bug. They now fall back to substring matching, so `迁移` returns results instead of nothing. Longer queries use the fast index.
- `npm audit`: **9 high → 0**.

## 🐛 Fixes

- **Several tasks in one turn are now one table.** Asking the agent to create 4 tasks rendered 4 cards of which only the last had working open/edit/delete buttons. Multiple tasks now render as a table — one row per task, streaming in as they are created, each row with its own actions; a single task keeps the familiar card.
- **Task cards no longer show a blank description or missing story points** — both were read from an always-empty field instead of the tool result.
- **`brave_search` is no longer offered when it cannot work.** It reads its key from an environment variable that has no Settings field, so on every shipped build it failed on every call — while its description told the model to use it _first_. It is now withheld without a key, `web_search` is described as the primary tool and performs its own HTTP fetch (so it works on the hosted gateway too), and a Qwen-specific rule that silently disabled web search for Qwen users was removed.
- **Markdown toolbar commands act on the editor you clicked.** H1/H2/H3, lists and quote were routed to module-level singletons that Milkdown rebinds on every editor load, so they silently did nothing in every editor except the last one mounted.
