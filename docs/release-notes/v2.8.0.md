# TomiLite v2.8.0

**Since v2.7.0** — the knowledge map can now be filled from your own work, and the strip of task counts under it is gone. A finished task, a month of reports and a meeting's decisions can each be folded into a note of your own, which then takes its place in the tree, gets links, and is found by search and semantic neighbours like anything else you wrote. Nothing is generated in the background: the free pass counts the sources, the second pass proposes notes, and nothing is written until you have read them.

## ✨ Features

- **Harvest knowledge out of finished tasks, report months and meetings.** One button on the knowledge map card opens a dialog that lists what is available. Each source becomes **one note**: a task distils what it was and how it was resolved, a month of reports folds that month's decisions and conclusions, a meeting folds its decisions and their reasons. All three land in your notes panel as ordinary notes — editable, searchable, linkable, and leaves in the knowledge map like any other note.
- **A month is one note, not thirty.** The dialog offers `task` / `report` / `meeting` as separate checkboxes and a time range (30 days, 90, a year, or everything), so a first run over years of history can start small. The current month is included from its first report, and pressing again mid-month merges into the same note rather than opening a second one.
- **The count comes before the bill.** Opening the dialog and changing its scope calls the server's free listing, which reports how many sources are eligible and — this is the part that matters — why the rest are not: *38 have no content to work from*, *22 have been harvested already*, *5 are still open*. Those five states look identical on screen and need opposite responses from you, so each is named rather than collapsed into "no results".
- **Every proposed note is editable before it is written.** The title and the whole body are yours to change. A draft about a month of work is a first draft, and without this the only verdict available would be "discard the whole thing".
- **Nothing is written that you did not read.** The text you approve is the text that gets stored — the model is not asked again at write time. If a note was edited (by you, or by the agent) between the review and the button, that write is refused and reported rather than overwriting the edit.

## 🔧 Changes

- **The project pulse is gone from the knowledge map.** The todo / in progress / done counts and the two lists of recent tasks and reports have been removed. It described a project and contained no knowledge, which is the opposite of what a map of notes is for. Task counts are still on the board's own tab badges, where they belong — `issue.taskCounts` is untouched and is now its only caller.
- **The knowledge map's empty state now offers the harvest.** With the strip gone, an empty library would have shown a card saying "no notes yet" and a button that cannot do anything. That screen is the one a new user lands on, so it now explains where notes come from and carries the button that makes some.
- **"Imported" is no longer stamped on notes that were written here.** The badge fired on any note carrying a source, which already mislabelled chat summaries and would have mislabelled every harvested note — your own finished work, described as something that came from elsewhere. Only actual imports (`import:*`) get it now.
- **Categories are labelled in one place.** The notes list used to print the raw value for any category it did not know, so a harvested note would have read `task` in the list and "来自任务" on the map. Both screens now call the same table (`apps/web/src/lib/noteCategory.ts`), which also names the three new categories.
- **Importing notes is one button now.** The import dialog used to carry a section per file format — a hidden input, a button and its own explanation of the same four facts, four times over. It has one: pick any supported file in a single selection and the file's own extension decides which importer reads it. Markdown (`.md`, `.markdown`), plain text (`.txt`), saved web pages (`.html`, `.htm`) and single-page web archives (`.mht`, `.mhtml`) can be mixed in one pick, and the run reports once — one progress bar, one summary. Formats are named by extension rather than after the application that writes them, which is also what let four sections collapse into one. Nothing runs when the file dialog closes: the picked files are listed, each one marked with what will read it, and the import starts on the button under that list — so a wrong pick is caught by looking at it rather than by reading a summary afterwards.
- **A saved web page imported this way arrives without its images.** An `.html` export keeps its pictures in a `<name>_files` folder beside it, and a file pick cannot see into a folder — so every image becomes a placeholder line, counted in the summary and named in the details. The dialog says so before you start rather than letting the summary be the surprise. `.mht` is unaffected: it carries its images inside the same file, which makes it the format to prefer when a note's pictures matter.
- **`.enex` import is gone.** The picker no longer offers the extension and nothing can read one. Formats are also no longer listed by application name in the dialog, because that is what made one application's export menu look like a feature of this one.

## ⚠️ Notes

- **The harvest is bounded per run.** 12 sources per run, one model call each. Both limits are reported: the dialog says how many are over this run's limit and will come first next time, and a source that was too long to read whole says so on its own note. 12 calls is a cost you can see and approve; 300 is not, which is why a full backlog takes a few presses rather than one.
- **The dialog shares one spending brake with chat distillation.** If your quota runs out, the harvest stops and says when spending resumes — and so does the background chat summary. The brake is a fact about your account, not about a feature, and a second one would let one screen say spending is paused while the other happily kept trying.
- **The model is not asked for `[[links]]`.** It has no way to know which titles exist in your library, so the links it wrote would resolve to nothing — or to the wrong one of two same-titled notes. Use **Find links** in the notes panel afterwards; that path knows what is in the library and shows you the proposals.
- **Harvesting the same source twice is a merge, not a second note.** The dialog says "merges into …" when a note already exists for that source, the previous note is fed back to the model as material, and any `[[links]]` already in it are preserved. It will not ask again unless you tick **Re-harvest everything**.
- **Notes you already imported from `.enex` are not affected by this release.** The importer is gone, the notes are not: they open, search and edit exactly as they did, and the notes list still badges them as imported. What changed is that you cannot import *more* of them. One thing did get quieter: an encrypted passage `<en-crypt>` was detected and counted per note by that importer alone, so a summary can no longer tell you that it skipped one — an encrypted passage in any of the remaining formats is imported as ordinary text and counted as nothing in particular.
