# TomiLite v2.5.0

**自 v2.4.0 起** —— 你已有的东西可以搬进来了。笔记来自 Markdown 文件夹或印象笔记导出文件；公司 Redmine 上指派给你的工单，会以只读镜像的形式出现在任务看板上，于是健康分、晨间简报和 Agent 第一次看得见这些从来没进过这里的工作量。另外还有设计这个功能时发现的三个潜在缺陷，其中两个会吃掉数据。

## ✨ 新功能

- **从 Markdown 文件夹或印象笔记 `.enex` 导出文件导入笔记。** 设置 → 导入。选一个文件夹，它下面（含子文件夹）每个 `.md` / `.markdown` 文件成为一篇笔记；选一个 `.enex`，笔记本里的每一篇都在。笔记本名或顶层文件夹名成为笔记的**分类**，导入的东西按你原来的归档方式分组，而不是堆成一片。
  - **重复导入会跳过已有的。** 匹配依据是笔记的来源（文件夹里该文件的路径；`.enex` 则是创建秒数加标题），所以同一个导入跑第二遍会报「跳过 N 篇」，什么也不改。**覆盖**是一个单独的选项，默认关闭 —— 第二次导入同一个文件夹，绝不能悄悄抹掉你在两次之间做的编辑。
  - **图片内嵌，其他附件留一行占位。** 图片变成内嵌数据，读起来和原文一样，但有大小上限；其他附件留一行写明文件名。上限刻意压得小：搜索索引会把每篇笔记的正文再存一份，所以图片多的笔记会让数据库按大约两倍体积增长，同时几乎匹配不到任何有意义的查询。
  - **加密的印象笔记会说明情况。** 正文是 `base64:aes` 密文、或包含 `<en-crypt>` 的笔记在这里解不开 —— 印象笔记不导出密钥 —— 它作为占位并计数导入，而不是变成一篇看起来空白的笔记。文案会说清原因，免得读起来像解析失败。
  - **笔记编辑器的分类菜单现在会显示它真正的值。** 那个下拉只有四个固定分类，而应用早就在写第五个（`chat`），而 `value` 匹配不到任何 `<option>` 的 `<select>` 会渲染成**空白** —— 于是那些笔记看起来没有分类，而为了「修好」它随手选一项，就把这篇笔记永久移出了它原来的笔记本。现在无法识别的分类会作为列表里的一项自己出现。
- **导入 Redmine 上指派给你的工单。** 设置 → 导入 → 从 Redmine：填服务器地址、API key、项目，TomiLite 就会按计划拉取该 key 对应用户名下的工单（启动后 4 分钟一次，之后每 30 分钟一次），另有**立即同步**按钮，以及一个**预览**，告诉你这次同步会做什么而一个字都不写。
  - **单向，且在这里只读。** 任何东西都不会写回 Redmine，镜像工单在看板上不能编辑、不能删除、不能拖拽 —— 下次同步会覆盖本地修改、把本地删除重新建回来，所以这些控件是**不存在**，而不是点了没用。这条单向正是这份副本可以安全留着的前提。
  - **这些工单在所有地方都算你的任务。** 它们进入看板计数、首页总计、健康分、晨间简报的逾期清单，以及 Agent 对你工作量的认知。这是有意的：同步向 Redmine 要的是**指派给你**的工单，所以进入统计的是你真实的队列，不是某个项目的吞吐量。
  - **你的任务保留你的编号，它们的保留它们的。** 镜像行显示 Redmine 自己的 `#1234` —— 你同事、commit 和邮件线程都在用的那个号 —— 而 `TL-` 编号留给本应用创建的任务。这也意味着 commit message 里提到 `#1234` 时，不再能从 Git 面板关掉一条镜像工单；关联本身照旧记录。
  - **关于服务器的词表，什么都不猜。** tracker / 状态 / 优先级都从你的服务器读取并缓存，因为它们是每台服务器各自的、且通常是你的语言。工单是否关闭，只看状态自己的标志位，绝不看名字，所以把「Closed」改名不会污染映射。
  - **不想要的工单可以从任务编辑器里「解除关联」**：它变成一条你自己的普通本地任务，可以编辑，同步也不再维护它。解除关联时会明确告诉你该工单会在下次同步时作为新副本回来 —— 那是清掉关联这个动作的诚实后果，不是 bug。
  - **断开连接给三个选项，并且必须选一个**：保留镜像任务、全部解除关联变成本地任务、或删除。没有默认值，因为「保留」会留下一批既只读、又不再能刷新的行 —— 这个死胡同应该是你的选择，而不是你掉进去的。
  - **明文 `http://` 允许使用，但会明确提示。** 内网 Redmine 是常态，所以不强求 TLS；设置页直说这一段的 key 是明文传输。API key 本身在磁盘上加密存储，且从不回传给界面。
- **导入标签页会在大批量导入前提醒你。** 它读取当前笔记数，并在这次导入会把总数推过「知识地图降级成分类树」的阈值时告诉你。

## 🐛 修复

- **每小时清理任务是在删除已完成的任务，不是在隐藏它们。** 那段代码自己的注释写着「从界面隐藏，从不删除」—— 对 commit 和邮件成立（它们是打标记归档），对任务不成立：它是直接删除，连同任务的评论、变更记录、Git 关联和看板卡片一起，若有子任务则把子任务留成没有父任务的孤儿。你完成之后就再没碰过的任务，90 天后就没了。**镜像工单现在被排除在这个清理之外**，而这正是紧急的那一半：已关闭的 Redmine 工单会映射成「已完成」，而已关闭的工单绝大多数都超过 90 天，同步游标又早已越过它们 —— 于是导入 400 条工单会在一小时内变成 87 条，永久且没有任何报错。清理**仍然删除你自己**那些陈旧的已完成任务，与之前一样；只是这件事现在写在它发生的地方，而不是被描述成一次隐藏。
- **笔记面板为了显示一个列表，把每篇笔记的完整正文都加载了。** 打开笔记会把整个库 —— 正文、向量和全部 —— 拉进窗口并一直留着，然后 20 条一页地翻。每次刷新都再付一遍。现在列表是一个投影（标题、分类、时间），正文在你打开某篇时才取 —— 而刷新路径本来就是这么做的。
- **你自己的任务不会再被导入挤出任务列表。** 看板最多取 200 条任务、按最新排序，而角标是对全集计数的 —— 所以几百条刚同步进来、时间戳都很新的工单可以占满这 200 个名额，让某个页签一行都不渲染，而它的角标写着 37。现在你的任务排在镜像之前、优先占名额；角标仍然统计全部。
- **同步进行中新建的任务不会再重号。** `issue.create` 是先读当前最大任务号、再插入，两步在事务之外。同步恰好在这个间隙写入几百行时，就会出现两条同号任务，而所有按编号识别任务的地方 —— 编辑器、Agent、MCP 服务 —— 会任意挑一条。现在读号和写入在同一个事务里。
- **笔记的向量表示的是它的文字，不是它的截图。** 带内嵌图片的笔记会把整份 base64 交给本地嵌入模型，模型先把它 tokenize、再在 512 token 处截断 —— 于是一篇图片很多的笔记，它的向量描述的是图片数据而不是正文，语义搜索永远找不到它。现在 data URL 图片在嵌入前被剔除，对已有笔记同样生效。

## ⚠️ 说明

- **本版给 `Issue` 加了两个字段**（`source`、`sourceId`），`SCHEMA_VERSION` 25 → 26，都是纯追加的 `ALTER TABLE` —— 不重建表，不动任何一行。所有已有任务在这两列上都是 `NULL`，而 `NULL` 正是「本应用写的」这个值；所有已有的写入路径也继续写 `NULL`。
- **导入是一份副本，副本会变旧。** 镜像工单反映的是上次同步，不是最近五分钟；同步间隔 30 分钟，想更早就按**立即同步**。你的 Redmine 上的任何东西都不会被改动，永远不会。
- **导入的笔记以文件夹作为分类**，这与应用自带的四个分类并不重合。这是有意的 —— 分类记录的是这篇笔记从哪来 —— 而编辑器现在会正确显示它，而不是显示空白。
- **超过 100 MB 的 `.enex` 会被拒绝**，并提示你拆分导出。整个文件必须按文本读入，而给这个体积建一棵完整的文档树会把应用拖垮；按笔记本分别导出是变通办法。
- **`.enex` 解析器是全新的，尚未拿真实导出文件验证过。** 它是按格式规范写的；Markdown 文件夹导入与它没有共用代码。如果印象笔记导入出来的笔记是空的或格式不对，问题就在那部分，而一份真实样本文件是唯一能定论的东西。遇到请提 issue 说明文件的形态（不必附文件本身）。
- **Redmine 的 REST API 可能被服务端整个关掉。** 这时它返回的是 HTML 错误页而不是 JSON，TomiLite 现在会把它报成一个可读的失败，而不是崩溃。API key 被拒绝是另一种单独的报错，所以你能分清「接口被关了」和「这个 key 不对」。
- **如果你的 Redmine 只能通过代理访问，就会走代理** —— AI 功能用的那个系统代理设置。从外网访问内网 Redmine 时必须要它。
