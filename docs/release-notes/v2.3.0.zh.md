# TomiLite v2.3.0

**自 v2.2.0 起** —— 一次外观与减法的发布。深色模式来了，其余都是拿掉东西：底部导航从十项减到四项加「更多」，Agent 自己的流水账移出聊天区，五种空态收敛成一种，主题选择从工具栏搬进设置。没有新增 Agent 能力。

## ✨ 新功能

- **🌙 深色模式。** 明暗是一条新的轴，与四套主题彼此独立 —— 每套主题都有明暗两种。它是 React 渲染前就写好的 `data-mode` 属性，所以启动不会白闪；同时设了 `color-scheme`，让原生控件跟着走：日期与时间选择器、复选框、下拉菜单、滚动条不再是黑压压一片。
  - **要开这个模式，得先把 token 层修对。** 品牌色相关的着色此前是写死的 indigo —— 按钮阴影、更新条、引用块 —— 也就是说四套主题里有三套**在亮色模式下就已经**在蓝/绿品牌色下面画着 indigo 阴影。现在它们都从实时的品牌色派生。品牌填充上的 `color: #fff` 改走 token，另有一个标题用 `--surface` 当文字色。
  - **三个亮色模式下的颜色不达 WCAG AA**，已调整：pipeline 的次要文字（3.00:1）、hub 的品牌色作填充（4.23:1）、canvas 的品牌色（4.51:1，刚过线没有余量）。
  - **你已有的笔记是安全的。** 富文本的高亮色与文字色是**存进文档里**的，当初是按白底挑的。深色模式下它们会变成浅粉底压浅色字 —— 完全不可读，而且是在你已经保存的笔记里。现在它们经主题解析，旧笔记会自己换色。
- **底部导航是四个去处加一个「更多」。** 原来有十项，而十项从来就放不下：十个 `min-width: 56px` 的条目加上弹层自身的内边距需要 592px，而聊天列只保证 360px。于是**恰恰在面板打开时**——也就是真正干活的时候——这一行会横向滚动。四项加触发按钮只需 280px，溢出消失。
  - 第五项原本是**「对话」**，这次是删掉而不是挪进「更多」。聊天列是面板的**兄弟节点**，永远不会被面板盖住，所以「跳转到对话」什么都不会新露出来 —— 那是一个被标成「去处」的关闭按钮，而每个面板自己的 ✕ 已经在做这件事。
  - **「更多」上是一个纯红点，不是数字。** 它一度显示未读邮件与待批 MCP 之和，而这是两个不相干的队列——那个「3」回答不了任何人的问题。列表里每一项自己的数字仍然保留。
  - **弹层锚定在打开它的那个按钮上**，并且**左边缘**与触发按钮对齐。若改成右边缘对齐，一个 172px 的列表会整个挂到一个 56px 按钮的左边：实测列表 319–491、按钮 435–491，正好盖在「任务」和「会议」上，而它所属的那个按钮反而在自己的右边缘之外。
- **会话列表按日期分组** —— 今天 / 昨天 / 更早。因为标题不再自动生成之后（见下方修复），「谁是哪个 Chat 26」唯一能靠的就是时间。
  - **「更早」默认折叠**，而且只有它折叠：它没有上界，而今天和昨天才是你会回头找的。分组头带上被折叠的条数，并且**当你正在聊的会话就在下面时会自己展开** —— 否则折叠状态下侧栏会没有任何高亮行。手动折叠之后它不会再次自作主张弹开。
- **设置 → 外观。** 工具栏上原本有五个主题圆点加一个日/月按钮，现在从聊天头部完全撤掉；主题与明暗搬进了真正的设置页，由一个 store 作为它们共同读取的唯一来源。
- **五个面板共用同一个空态。** 笔记、任务、报告、会议、邮件各有各的——其中两个干脆就是一个 `—`，还有一个在「只是搜不到」时也显示「还没有笔记」。现在收敛成一个组件：图标、一句话、一个真正能走通的按钮。
  - **搜不到是另一屏，和面板本身为空不是一回事**，两者画得也不一样：空面板要解释自己并给出动作，搜索无结果只有一行。
  - **空态不提供不存在的创建流程。** 笔记、任务、报告都是**保存时才创建**，所以它们那个按钮是清空编辑器——与各自工具栏里原有的重置是同一个动作。会议那个按钮走的是录音同意弹窗，而不是绕过它。

## 🐛 修复

- **Agent 自己的操作流水账不再出现在聊天里。** 每次开/关面板都会追加一条 `🔔 你打开了 X 面板`，一个会话里连续六条零信息量的气泡能占掉半屏。这些信号仍然照常产生、仍然送达模型——那正是它们的用途；只是在消息上打了个标记，让渲染层跳过。**Agent 看到的东西一条没少**，token 计量也仍然统计它们。
- **会话标题恢复生成。** 自动起标题的代码早就写好、也接在了每次发送上，却被永久关死 —— 它的守卫只承认标题**恰好等于** `Chat`，而会话创建出来是 `Chat 26`。只修守卫不会有任何变化：它写的是**侧栏根本不读**的另一份 store。现在它写在它要改的那份列表旁边，并且落库，重启后标题不会退回占位符。
- **时间戳按其真实的 UTC 解析。** `updatedAt` 按 UTC 写入却按本地时间解析，所以在 UTC+8 下，早上 8 点前做的任何事都会被打上「前一天」，归进「昨天」。
- **`quantum` 主题里有两个颜色是同一个颜色。** `--brand` 与 `--green` 都是 `#76b900`，于是「新对话」、当前导航项、所有完成态在肉眼上无法区分——这是**一个主题里的 token 撞车**，不是绿色用得多。成功绿改为 `#0d904f`。顺带修好一个症状：会话 token 条的「低」和「中」两档在那个主题下原本也是同一个色。
- **聊天列的字号现在是一个「阶梯」。** 它在用 9、10、11、12、13px，其中 78 处里有 51 处**背后没有任何 token** —— 阶梯是 11/12/14/16/20/24。合并到已有的两档（9/10/11 → `--text-xs`，12/13 → `--text-sm`，共 81 处）。这些差异本来也没有在表达层级：卡片里字段的标签是 9px 而**它自己的值**是 10px；工具卡的**名字**是 10px，而它下面的正文是 12px —— 层级是反的。真正的层级一直由字重和颜色承担。
- **会议面板不再憋屈。** 放宽到 `clamp(420px, 46%, 680px)`，这一改顺带挖出旧规则的一个缺陷：面板宽度可以超过整行剩下的空间，把整个应用推出横向滚动条——在 900px 的最小窗口下**原本就已经在溢出**。两条规则现在都带拟合上限。
- **反馈的提交按钮在提交时一言不发。** 它的「提交中」状态与禁用状态都不可达 —— 有一个调用从来没被发出去，所以整个请求过程中按钮一直是可点的、也没有任何提示。
- **邮件分类标签在深色模式下不可读。** 它的配色是亮色模式的浅色底，浅底压浅字。
- **白天/夜晚图标是全应用最后两个写死的渐变**，也是仅有的两个不跟随主题的饱和色。
- **没有行动项时不再显示「0 个行动项」。**
- **删掉了一个失效的更新弹窗。** 它导出一个检查 hook 和一个弹窗组件，而没有任何地方引用它们——没有静态导入、没有动态导入、配置与 html 里也没有字符串引用。真正在用的更新流程是另一个组件，自己注册监听，所以这一个的监听从来没跑过。

## ⚠️ 说明

- **无 schema 变更。** 本次发布不会迁移你的数据库。
- **主题即时生效并会被记住**，但冷启动时窗口仍由主进程先涂成浅色，渲染进程才加载，所以深色用户可能看到一帧白。该设置存在渲染进程里，主进程读不到；要彻底修得把偏好落到磁盘文件上。
- **「更多」弹层用的是 CSS anchor positioning**，属于 Chromium 特性。TomiLite 只在 Chromium 上发布，所以这不是兼容性缺口；但它前面那两条 inset 声明是作为回落保留的，在不支持该特性的渲染器里，弹层会退回到导航条自身的左边缘。
- **已知且未修复的问题，记录在此以免被当成遗漏：**
  - **四个主题的成功绿在亮色底上都不达 AA**（pipeline 2.18:1、hub 3.19:1、canvas 与 quantum 3.93:1）。根因是 `--green`、`--amber`、`--purple`、`--blue` **没有任何主题做过明暗覆盖**，只有 `--brand` 有。给这四个语义色各配一套明暗值是一项独立工作，涉及 4 主题 × 4 token × 2 模式，不在本次发布内。
  - **应用里有三套并行的 i18n 系统**（`@/lib/i18n`、`@/i18n/translations`，以及组件内就地写的三语三元表达式）。合并它们是一次跨全仓的机械改造，与本次发布无关。
  - **`ChatSession.updatedAt` 一个字段混了两种时钟** —— `createSession` 走数据库默认的 `localtime`，而 `addMessage` / `renameSession` 写的是 UTC。于是新建的空会话会排在真实会话前面。要修得动 schema、迁移，以及依赖这个 UTC 戳的 distillation 任务。
  - **文档语言恒为英语**，与界面语言无关。影响的是读屏与断词，不是视觉。
