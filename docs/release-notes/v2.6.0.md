# TomiLite v2.6.0

**Since v2.5.0** — TomiLite now speaks MCP properly. The claim that it "exposes your tasks to Claude Code" has been true of the *tools* for a while and of the *protocol* never: the only way in was an HTTP endpoint that looked like MCP without being it, which no stock client could connect to. There are now two real transports, both protocol eras, and a settings page that hands you a config that actually works. Along the way: three divergent copies of the tool list collapsed into one, and four defects fixed, two of which you could hit today.

## ✨ Features

- **TomiLite is now a standard MCP server.** Settings → API Keys shows a ready-to-paste config for both transports, with this installation's real paths filled in — the installer lets you choose its own directory, so the paths cannot be written down in advance.

  - **stdio.** The config starts `TomiLite.exe` itself as the server. The installer ships no `node.exe` and no `tsx`, so the app runs its own bundled script under `ELECTRON_RUN_AS_NODE=1` — a mode in which Electron never loads its main script: no window opens, no single-instance lock is touched, and the process is simply a Node child of your MCP client.
  - **StreamableHTTP.** `POST http://127.0.0.1:<port>/api/mcp` with the key in an `X-Api-Key` header, for clients that speak HTTP rather than stdio. Local origins only; `GET` and `DELETE` answer `405` because there is no SSE stream and no session to enumerate.
- **Both protocol eras are served, and the era is decided per request.** The current revision (2026-07-28) removed the `initialize` handshake entirely — every request carries its own `_meta` envelope and the server is stateless — while every client in the field still opens with `initialize`. TomiLite answers whichever it is asked, chosen by a single fact (does the request carry an envelope), which is why the HTTP endpoint needs no session id and no server-side state to lose. A client probing for the new revision gets a real answer and a version list; one that does not gets the old handshake.
- **Waiting for approval no longer looks like a timeout.** Approving a write used to happen inside a five-minute HTTP long-poll, and MCP clients abandon a tool call somewhere near a minute — so the model was handed a transport error it could not explain. The wait is now short by design, and the call that runs out of patience comes back saying plainly that **nothing has been executed yet**, that the action is waiting in the MCP panel, and to call again with the same arguments or collect it with the new `get_task_result` tool.
- **An approval that arrives late is not wasted.** The panel's Approve button executes the tool itself and keeps the result on the task, so approving after your client has given up still performs the action — and `get_task_result` still returns it.
- **A read never asks for approval, and never has to.** Read-only calls are answered directly and are no longer filed as approval tasks, so the same read repeated twice returns data twice.
- **`get_board_status`** joins the tool list — your kanban, column by column, with WIP limits and card counts — and a tool that was advertised but never implemented (`update_settings`, an unclear way to rewrite arbitrary configuration) is gone. Every tool that is advertised is callable; that is now checked end to end rather than by inspection.
- **API keys carry scopes that are enforced.** A key without the `write` scope cannot call a tool that does anything. Every key minted before this release already held `read,write`, so nothing changes for them — it starts mattering exactly when a third-party client holds a key, which is what this release makes possible.
- **Selected notes can be deleted in one action.** The notes list has always allowed multi-select, but selection had exactly one destination — export — so clearing out thirty notes meant thirty trips through the editor in a list that already had them ticked. The toolbar now grows a delete button whenever something is selected, the header checkbox selects the whole filtered result across pages, and the confirmation reports progress as it goes, because deleting is one round trip per note and a long selection would otherwise look like it had frozen. A run in which some notes fail says so, counting the ones that were actually removed — "N could not be deleted; the rest were" — instead of reporting the number it attempted. **One latent bug went with it:** "select all" filtered on note *bodies*, a field the list stopped loading when its projection was trimmed, so a search that matched a note's **category** would show you that note and quietly leave it out of the selection. Both now ask the same question.

## 🔧 Changes

- **Importing has moved out of Settings, into the panel that shows the result.** Notes import was a tab that filled your notes library; the Redmine connection was a tab that filled your task board; neither is a setting. Both are now dialogs opened from their own panel's toolbar, or from the empty state when there is nothing there yet — which is exactly the moment someone has notes or tickets somewhere else. **The import now refreshes the list it wrote into.** Previously it relied on the panel being re-entered, which stopped being true the moment the feature moved inside it.
- **Markdown import takes files, not a folder.** `Settings → Import`'s folder picker is gone; the dialog now takes any number of `.md` / `.markdown` / `.txt` files at once, which is what you actually have after exporting from somewhere. Two consequences, both handled rather than discovered: a file pick carries no directory, so the notebook — which used to be the subfolder name — is now an optional **Notebook** field in the dialog (leave it empty and the notes are filed as `imported`), and files are identified by name alone, so two same-named files picked in one batch are reported as skipped in the summary instead of one silently replacing the other. If you selected a *folder* to get subfolders filed as notebooks, pick the files instead and type the notebook name — the grouping is one field now.

## 🐛 Fixes

- **A retry after approval returned the status but not the answer.** The idempotent-replay path echoed the task's state and omitted its result, so a write that had been approved and executed came back with `approved` and nothing else — permanently, because the retry hit the same replay. The same omission meant a read-only call, which *was* being filed as a task, returned no data at all the second time you made it. Both are the same one-line cause.
- **`get_report` could return a 500 instead of an error.** Its schema declared `id` required while the runtime validator did not, so a call without one reached a database lookup keyed on `undefined`. There were two lists of required fields; there is now one, derived from the schema, which makes the disagreement impossible rather than merely fixed.
- **The MCP panel reported a successful approval as a failure.** The Approve button tested a field the backend has never returned, so every approval that worked rendered as an error. It now judges the status it actually gets.
- **The tool list, the risk table and the implementations were three separate lists that had already drifted** — one advertised 17 names, one implemented 15, one carried schemas for 14. Two names could be called, queue an approval, wait for a human, and then answer `Unknown tool`. They are now one catalogue, and a call to an unknown tool is refused as a protocol error *before* any approval exists to wait on.
- **A `POST` with an `X-Api-Key` from a browser failed its CORS preflight**, so no MCP call could be made from a page at all. `X-Api-Key` and the protocol's own headers are now permitted.
- **A non-localhost MCP client was asked for a token it had no way to obtain.** The endpoint's exemption from the desktop token tested for a prefix with a dot in it, which the bare endpoint URL does not match. The exemption is now exact.

## ⚠️ Notes

- **No new dependency.** The MCP protocol is implemented directly, as the existing client and server halves already were. The installer gained one bundled file, not a package tree.
- **Reinstall to get this.** The stdio script is a build artifact produced at pack time, so an upgrade that only replaces the database schema is not enough — use the new installer.
- **Pending approvals do not survive a restart.** The approval queue lives in the running app's memory. Quitting TomiLite discards anything still waiting: approve before you quit, or re-issue the call. Fixing it properly needs a new column in the audit table and is deliberately not in this release.
- **An API key's expiry date is shown but not enforced.** An expired key still authenticates. The column has never been format-checked across existing rows and a comparison written against the wrong assumption would lock every key out at once, so this needs a storage audit first. Until then, treat the date as a note to yourself and **revoke** any key you no longer trust.
- **A key that no longer works tells the model so.** Invalid and revoked keys are reported as a *tool* failure rather than a protocol fault, so the assistant can read "this key is invalid, regenerate it in Settings → API Keys" and pass that on, instead of your client showing an opaque protocol error.
- **`POST /api/mcp.execute` is unchanged.** Callers already integrated against the old endpoint — including anything following the previous instructions in Settings — keep working exactly as before. What was wrong with the old instructions was that they described a config no MCP client could use; the endpoint itself is fine, and it is now what both new transports call.
- **Feishu, WeCom and similar cloud platforms are not covered by this.** They are cloud services and need a publicly reachable endpoint, which is a different piece of work — a relay rather than a transport. The StreamableHTTP endpoint added here is the protocol half that work will reuse.
